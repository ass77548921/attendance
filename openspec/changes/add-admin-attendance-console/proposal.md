## Why

目前後台需求已經明確，但現行能力對「人工修正出缺勤且保留稽核理由」與「可由後台維護郵件發送參數」覆蓋不足，難以支援實際營運管理與稽核追蹤。需要一次性定義完整管理後台能力，並可在後端 API 尚未齊備時提供可落地的實作規劃。

## What Changes

- 建立或擴充管理後台 API 能力，支援查詢人員出缺勤、手動修改紀錄且強制填寫修改理由。
- 擴充出勤規則設定 API，支援上下班時間與規則參數管理。
- 新增郵件發送設定管理能力（寄件帳號、密碼、主旨樣板、寄件名稱等）與驗證流程。
- 擴充通知收件人管理能力，支援新增、停用、刪除、查詢。
- 擴充人員帳號管理能力，支援查詢、建立、停用與必要的角色存取限制。
- API 以後端契約優先定義，前端後台可依契約逐步串接。

## Capabilities

### New Capabilities
- `mail-delivery-settings`: 管理 SMTP 與通知郵件模板設定，包含安全儲存、啟用切換與測試發送。
- `attendance-adjustment-audit`: 提供管理員手動修正出勤紀錄能力，並保留修改前後內容、修改人與修改理由。

### Modified Capabilities
- `admin-dashboard`: 擴充管理後台需求範圍，納入人工修正出勤與更完整的管理操作流程。
- `attendance-rules`: 補強上下班時間與規則設定的管理行為與驗證要求。
- `notification`: 補強通知收件人管理與寄件設定耦合行為。
- `user-auth`: 補強後台人員帳號管理與角色授權邊界。

## Impact

- Affected code: 管理後台控制器、服務層、設定與審計資料模型、通知與認證模組。
- APIs: 新增 mail 設定與出勤人工修正端點，並擴充既有 admin 查詢/管理端點。
- Dependencies: 可能需新增加密或秘密管理機制以安全保存 SMTP 密碼。
- Systems: 後台管理流程、通知流程與稽核追蹤流程將受影響。
